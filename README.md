# Практична робота: Визначення шаблонних функцій

**Тема:** Визначення шаблонних функцій  
**Мета роботи:** Сформувати розуміння патерну «Шаблонний метод» (Template Method), навчитися виокремлювати незмінний каркас алгоритму в базовий клас і дозволяти похідним класам перевизначати окремі кроки; відпрацювати навички побудови ієрархій класів та дотримання принципів SOLID (особливо LSP і OCP) у прикладі «Калькулятор».

---

## Опис виконаної роботи

У ході практичної роботи створено консольний застосунок C# зі статичним класом `ArrayHelper`, який містить чотири узагальнені методи без використання бібліотеки LINQ:
1. `IndexOf<T>(T[] array, T value)` — лінійний пошук індексу елемента за допомогою методу `.Equals()`.
2. `Reverse<T>(T[] array)` — реверс елементів масиву за допомогою двовказівникового алгоритму.
3. `Min<T>(T[] array) where T : IComparable<T>` — пошук мінімального елемента з використанням методу `.CompareTo()`.
4. `Max<T>(T[] array) where T : IComparable<T>` — пошук максимального елемента з використанням методу `.CompareTo()`.
5. `PrintArray<T>(T[] array, string title)` — допоміжний метод виведення елементів масиву в консоль.

## 8. Короткі висновки про те, як параметр типу та обмеження вплинули на реалізацію кожного з чотирьох методів

- **Параметр типу `<T>`:** Дозволив написати універсальну логіку один раз для будь-яких типів даних, завдяки чому методи однаково коректно обробляють як масиви чисел (`int[]`), так і масиви рядків (`string[]`) без дублювання коду.
- **Метод `IndexOf<T>`:** Реалізований без обмежень, оскільки для перевірки на рівність використовується базовий метод `.Equals()`, доступний для абсолютно всіх типів у C# від класу `object`.
- **Метод `Reverse<T>`:** Реалізований без обмежень, бо алгоритм розвертання масиву на місці потребує лише доступу за індексами та перезапису значень через проміжну змінну типу `T`, що підтримується будь-яким типом даних.
- **Методи `Min<T>` та `Max<T>`:** Вимагають обов'язкового обмеження `where T : IComparable<T>`. Без нього компілятор забороняє операції порівняння для невідомого типу, а наявність обмеження гарантує наявність методу `.CompareTo()` і забезпечує перевірку типів ще на етапі компіляції програми.

## Відповіді на питання для самоконтролю

### 1. Що таке узагальнений метод і чим він відрізняється від узагальненого класу?
**Відповідь:**  
Узагальнений метод — це звичайний метод, який працює з універсальним типом `T` замість конкретного типу. Різниця в тому, що в класі тип `T` задається один раз при створенні всього об'єкта і діє на весь клас, а в методі тип підставляється окремо під час кожного його виклику.

---

### 2. Який синтаксис використовується для оголошення параметра типу узагальненого методу?
**Відповідь:**  
Параметр типу пишеться в кутових дужках `<T>` одразу після назви методу перед круглими дужками з аргументами:
```csharp
void MyMethod<T>(T item)
```

---

### 3. Як компілятор визначає тип-аргумент під час виклику узагальненого методу, якщо він не вказаний явно?
**Відповідь:**  
Він сам дивиться на тип змінної, яку ми передаємо в дужках методу. Якщо передали число `int`, компілятор автоматично розуміє, що `T` — це `int`.

---

### 4. Для чого потрібні обмеження параметра типу?
**Відповідь:**  
Щоб компілятор знав, що тип `T` точно вміє робити потрібні дії (наприклад, порівнюватися через `CompareTo`, створюватися через `new()` чи бути класом). Без обмежень компілятор сприймає `T` як звичайний порожній `object` і видає помилку на специфічні операції.

---

### 5. Як синтаксично задається обмеження параметра типу в C#?
**Відповідь:**  
Через слово `where` в кінці заголовка методу перед фігурними дужками:
```csharp
void Sort<T>(T[] a) where T : IComparable<T>
```

---

### 6. Чому метод IndexOf для масиву можна реалізувати без обмежень на параметр типу?
**Відповідь:**  
Бо для пошуку треба тільки порівняти два елементи на рівність. А метод `.Equals()` є взагалі у всіх типів у C#, бо він успадковується від базового типу `object`.

---

### 7. Чому методи Min і Max неможливо коректно реалізувати без обмеження параметра типу?
**Відповідь:**  
Бо компілятор не знає, як порівнювати невідомий тип на «більше» чи «менше» (знаки `<` і `>` для довільного типу не працюють). Щоб викликати метод `.CompareTo()`, треба обов'язково сказати компілятору, що тип реалізує інтерфейс порівняння.

---

### 8. Що станеться під час компіляції, якщо викликати метод з обмеженням where T : IComparable для типу, який цей інтерфейс не реалізує?
**Відповідь:**  
Програма просто не скомпілюється: Visual Studio підкреслить виклик червоним і виб'є помилку, що цей тип не підходить під обмеження.

---

### 9. Які ще види обмежень, крім IComparable, можна накладати на параметр типу?
**Відповідь:**  
- `where T : class` — тільки посилальні типи (наприклад, `string` чи власні класи);
- `where T : struct` — тільки прості значеннєві типи (числа, `bool` тощо);
- `where T : new()` — тип обов'язково повинен мати порожній конструктор без параметрів;
- `where T : BaseClass` — тип має бути спадкоємцем конкретного базового класу.

## Висновок
Під час виконання практичної роботи створено статичний клас `ArrayHelper` із чотирма узагальненими методами без використання бібліотеки LINQ.  
Методи `IndexOf` та `Reverse` реалізовано без обмежень на параметр типу, оскільки розвертання масиву потребує лише індексації та обміну елементів, а для пошуку достатньо базового методу `.Equals()`, який мають усі типи в C#.  
Для методів `Min` та `Max` використано обмеження `where T : IComparable<T>`, оскільки пошук мінімального й максимального значень вимагає порівняння елементів через метод `.CompareTo()`, що неможливо зробити для довільного типу без цього інтерфейсу.  
Роботу всіх методів успішно протестовано на масивах двох різних типів (`int` та `string`), завдання виконано повністю.
